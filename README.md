# ClearFairy for VS Code

作業しながら口に出した独り言（思考発話）と、VS Code 上の操作（Python の `.py` と Jupyter の `.ipynb`）から、コーディング中の判断とその理由を「意思決定ステップ」として記録する拡張機能。仕様はおおむね論文 ClearFairy（CHI 2026、[arXiv:2509.14537](https://arxiv.org/abs/2509.14537)）に従う。

- 音声認識はローカル（CPU）。sherpa-onnx の Whisper turbo を使う
- 言語モデルは Copilot の言語モデル API（`vscode.lm`）を使う
- 記録するのは手で書いたコードだけ。AI エージェント（Claude Code、Copilot のエージェントなど）の編集は除く

## 使い方（Phase 3）

1. ステータスバーの「🎤 ClearFairy」で作業の記録を始め、もう一度押すと止める
2. 記録中は、たまった発話と操作から少しずつ意思決定ステップ（判断・理由・経緯）を作る（15 秒手が止まったとき、または 40 秒ごと。質問は判断の 30 秒ほど後に出る）。**業務・データ固有の判断**で理由が弱い・無いものには、確認の質問を出す
   - 質問はその判断のコード行・セルの上に「❓ ClearFairy: …」と出て、ステータスバーに「💬 質問 n」と件数が出る。作業は止めない
   - 答えるのはサイドバーの「ClearFairy → 確認の質問」から、好きなときに。文字か「🎤 音声で答える」（記録中は同じマイクで受け、作業の文字起こしには混ぜない。聞いている間はステータスバーに「回答を聞いています」と出て、15 秒話さないと自動で終える。黙っている間の「ご視聴ありがとうございました」などは入れない）。答えると、その判断の理由に反映する。答えたくなければ「答えない」。音声の聞き違い（店名など）は、入力欄で直してから送ってよい（聞き取りの途中で直しても、続きは末尾に足されるだけで、直した分は消えない）
   - 同じ論点の質問は重ねて出さない。ステップは「判断（扱い方・処理・見せ方を選んだ）」と「確認だけ（列の中身や分布を見ただけ）」に分け、確認だけのステップには質問しない。読み込むファイルの指定を直すなどの段取りにも聞かない（何をどう話せば残るかは「[話し方](#話し方何をどう言えば残るか)」）
   - 質問の前に、本人の過去の判断（このワークスペースの前の記録と、同じ記録の前の判断のうち、理由がはっきりしていたもの・質問に答えたもの）から理由を推測する。具体的に重なる判断が無ければ推測しない。過去の判断が多いときは、直近のものと、今の判断と言葉（列名・関数名・漢字やカタカナの語）が重なるものを選んで LLM に見せる
     - 前の記録で説明した理由からの推測で足りるなら、質問は作らず「💡 前に説明した理由から推測しました。合っていますか？」と確かめるだけにする（記録をまたいで同じことを聞き直さない）。同じ記録の前のほうで自分で話した理由で足りるなら、何も出さない
     - 推測で埋まらない点があれば、その点を聞く質問に「💡 過去の判断からの推測」を添える
     - 「合っている」でそのまま回答に、「直して答える」で推測を入力欄に入れて直し、「違う」で推測だけ取り下げる（確認だけの項目なら、理由そのものを聞く形に変わる）。推測を見ながら文字や音声で答えれば、補足として推測と合わせて理由に反映する。元にした過去の判断は推測の下に出る
3. 止めると残りを処理し、小作業のまとまりを作る。終わったら「記録を見る」「質問に答える」で開ける（記録を止めた後でも答えられる）
4. 後から見るときはコマンド「ClearFairy: 記録を見る」、作り直すときは「ClearFairy: 記録から意思決定ステップを作り直す」（回答済みの質問があれば確認する）

記録はワークスペースの `.clearfairy/sessions/<日時>/` に残る（`.clearfairy/` は git に載らない）。

| ファイル | 中身 |
|---|---|
| `session.json` | 概要（開始・終了、モデル、マイク、件数） |
| `utterances.jsonl` | 発話ごとの文字起こし（実時刻付き） |
| `actions.jsonl` | 操作（編集・閲覧・セル実行・ターミナル・デバッグ・エラー表示）。型は `src/capture/actions.ts` |
| `events.jsonl` | 生のイベント（操作のまとめ方を見直すとき用） |
| `images/` | セルの画像出力 |
| `audio.wav` | 録音（設定 `clearfairy.speech.keepAudio`） |
| `sentences.json` | 文に分けて補正した文字起こし（補正前の文と、除いた雑音の印付き） |
| `steps.json` | 意思決定ステップ（判断・理由・経緯、理由の評価、確認の質問と回答、過去の判断からの推測と確かめた結果、結び付いた発話・操作）と小作業のまとまり |
| `answers.jsonl` | 記録中に音声で答えた回答の文字起こし |
| `pipeline/` | ステップを作るときの LLM との入出力（プロンプトの調整用） |

## 話し方（何をどう言えば残るか）

残したいのは、一般的なプログラミングの知識ではなく、**このデータ・この業務だからこその理由**（データの意味、業務の決まり、何を比べたいか）。独り言は、次のように話すと残りやすい。

| 場面 | 話し方 | どうなるか |
|---|---|---|
| 気づいて、扱いを決めた | 気づいたこと・どうするか・なぜかを続けて言う（例:「quantity にマイナスがある。返品だから売上からは除く」） | 判断として、理由付きで残る。質問は出ない |
| 扱いを決めたが、理由をうまく言えない | 黙って直すだけでよい（例: `quantity > 0` で絞る） | 理由の無い判断になるので、その場で質問が出る。答えれば上と同じく残る |
| 気づいただけで、扱いはまだ決めていない | 気づいたことの**訳**まで言う（例:「吉祥寺だけ少ない。8 月開店だからか」） | 確認だけのステップとして残り、説明は過去の説明としてたまる（記録を見る画面で「説明あり」）。質問は出ない |
| 中身を眺めているだけ | 何も言わなくてよい（例: 列を順に `value_counts` する） | 確認だけのステップとして残る。質問は出ない |

- 一度説明したこと・答えたことは、次からの推測の元になる。同じ記録の中で同じことを繰り返し言う必要はない。前の記録で説明したことに関わる判断では、質問の代わりに「前に説明した理由から推測しました。合っていますか？」と確かめるだけになる
- 推測に使う過去の説明は、このワークスペースの `.clearfairy/sessions/` にある前の記録から読む。別のワークスペースの記録は使わない
- 作業中の独り言の聞き違いは、同じ時間帯のコード・セルの出力に出てきた語・同じ記録で前に直した文を手がかりに自動で直す。店名のような固有名詞は、セルの出力（`value_counts` の表など）に出ているか、近く（同じ区切りの 40 秒ほど）で正しく聞き取れた言い方があれば直りやすい。一度直ると、同じ記録のその後の同じ聞き違いも直る
- 「〜だからか」のような推量でも、本人が口にした説明として扱う。後の記録でその説明から推測した確認が出たとき、違っていれば「違う」で取り下げられる

## 開発

```sh
npm install
npm run build        # dist/ に束ねる（npm run watch で監視）
npm test             # テスト用の VS Code を別に起動して統合テスト（ログインはしていない。ワークスペースは test/workspace）
npm run test:unit    # vscode に依存しない処理の単体テスト
bash scripts/download-models.sh sherpa-onnx-whisper-turbo sherpa-onnx-zipformer-ja-en-reazonspeech-2025-01-17
# 統合テストで流す読み上げ音声（.cache/testdata/tts/haruka-desktop.wav）を Windows の音声合成で作る
powershell -File scripts/make-tts.ps1 -SentencesJson scripts/think-aloud-ja.json -OutDir .cache/testdata/tts -Voices 'Microsoft Haruka Desktop'
```

- **Ctrl+Shift+B**（タスク「開発ホストを開く」）で、ビルドしてから `spike/playground` を開いた開発ホストが立ち上がる。VS Code 1.144 では F5（デバッガ付き）で開くと拡張機能のプロセスが起動直後に落ちる（終了コード 134）ので、デバッガは付けない。playground では音声認識モデルにリポジトリの `.cache/models` を使う（`spike/playground/.vscode/settings.json`）
- Copilot の言語モデルはサインイン済みの VS Code の中でしか呼べないので、開発ホストに外から依頼を出せるようにしてある（`src/dev/jobs.ts`、開発ホストでだけ有効）

  ```sh
  node scripts/dev-job.mjs '{"type":"ping"}'
  node scripts/dev-job.mjs '{"type":"llm","messages":[{"role":"user","content":"こんにちは"}]}'
  node scripts/dev-job.mjs '{"type":"reload"}'   # 新しいビルドを読み込み直す（記録中は断る）
  node scripts/dev-job.mjs '{"type":"pipeline","session":"<日時>"}' --timeout 1500   # 記録からステップを作り直す
  node scripts/dev-job.mjs '{"type":"questions","session":"<日時>"}'   # 未回答の質問だけ作り直す（prompts/question.md の調整用。"all":true で答えた質問も、"dry":true で保存しない）
  node scripts/dev-job.mjs '{"type":"infer","session":"<日時>"}'   # 質問した判断の理由を過去の判断から推測し、実際の回答と並べる（保存しない。prompts/infer.md の調整用）
  node scripts/dev-job.mjs '{"type":"replay","session":"<日時>"}' --timeout 1500   # 記録を元の間隔で記録中の処理に流し直し、質問の遅れを測る
  node scripts/dev-job.mjs '{"type":"answer","session":"<日時>","step":"<ステップ id>","text":"<回答>"}'
  node scripts/dev-job.mjs '{"type":"openSession","session":"<日時>"}'
  ```

- `spike/playground/` は開発ホストで開く練習用のワークスペース。git に載せているのは設定（`.vscode/settings.json`）、Python 環境（`uv sync --project spike/playground`）、練習用の売上明細を作る `make_sales.py`（`sales_2026.csv` を作る。乱数の種は固定）だけで、練習で作るノートブック・データ・グラフは載せない（`.gitignore`）

## 構成

| ディレクトリ | 中身 |
|---|---|
| `src/speech/` | 録音・VAD・音声認識の子プロセス（`worker.ts`）と、その呼び出し・モデルの取得 |
| `src/capture/` | 操作のまとめ（`actionRecorder.ts`）と生のイベント（`eventLog.ts`） |
| `src/session/` | 作業セッション（録音と操作の記録を同時に開始・停止して保存） |
| `src/llm/` | Copilot の言語モデル |
| `src/pipeline/` | 記録から意思決定ステップを作る処理（論文の CLEAR・要約・理由の評価・質問・理由の推測）。本体は `engine.ts`、止めた後にまとめて処理するのが `run.ts`、記録中に少しずつ処理するのが `live.ts`、推測に使う前の記録の判断を集めるのが `history.ts` |
| `prompts/` | LLM へのプロンプト（毎回ファイルから読むので、拡張機能を読み込み直さずに調整できる） |
| `src/ui/` | ステータスバーのボタン、記録を見る画面、確認の質問（`questions.ts`） |
| `src/dev/` | 開発用の依頼の受け口 |
| `src/spike/` | Phase 0 の検証用コマンド（手順ページ） |
| `test/` | 統合テスト（`test/unit/` は単体テスト） |
| `scripts/` | 開発用のスクリプト（モデルの取得、テスト用の読み上げ音声の生成、開発ホストへの依頼） |
